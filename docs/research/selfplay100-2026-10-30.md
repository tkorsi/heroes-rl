# One hundred self-play games from checkpoint 1728

## Prospective protocol

On 30 October 2026, the user authorized a 100-game self-play training experiment
to examine hero travel, inactivity and termination by limits. This supersedes
the earlier explanation-only instruction for this separate experiment. The
unfinished Nullkiller campaign remains preserved at checkpoint 1728, with 604
original-target games remaining and sequence 1369 next.

The experiment starts from the complete verified checkpoint 1728, including
model, Adam, global and minibatch RNGs, progress, sampler and archived pool.
It uses its own durable output, checkpoint pointers, ownership and seed ledger.
The existing campaign's fifteen protected state/evidence files must retain their
hashes and sizes. No cloud service or external model is used.

The target is 100 physical games in 25 four-game PPO batches. Each batch uses
an immutable copy of its starting learner as the opponent. Learner seats are
Red, Blue, Red, Blue, giving 50 games per learner seat. Only the selected learner's
trajectory enters PPO; the other player's actions and memory remain separate.
The opponent refreshes only after a complete verified update. This declared
opponent-distribution change is not an acceleration or an identical-policy comparison.

The ordinary hero-management-v2 map, model architecture, PPO/Adam settings,
terminal-only rewards (+1 win, -1 loss, 0 ordinary transitions), revealed-target
support and existing interaction budgets stay unchanged. There are no exploration
bonuses, demonstrations, strategic masks or hidden-information inputs. Production
CPU performance telemetry remains disabled.

Limits stay at 365 game days, 4,960 ordinary choices plus 160 reserved mandatory
choices, with a hard maximum of 5,120 choices per player. Both players now have
neural choices, so the sum can reach 10,240; this does not double the learner's
budget. Mandatory dialogs and capability choices remain policy-controlled.
The existing bounded post-cutoff technical continuation is excluded from policy
experience and cannot answer a mandatory choice. Each collector has the existing
600-second deadline. Collection and verification share the parent configuration's
2,400-second training phase; the update phase ends at its existing 10,740-second
offset from batch start. Each phase retains the 30-second cleanup reserve and is
capped by the campaign's ten-hour maximum safety budget.

A natural terminal is a win/loss. A replay-verified collection/day cutoff is
unscored and uses a real own-decision value bootstrap, as in the existing PPO
contract. A wall timeout, unsupported action, replay mismatch or other technical
failure is unscored, excludes the entire unfinished batch and stops the campaign.
No failed attempt is retried with the same seeds or silently replaced. Every
complete update is restored from its saved model/Adam/RNG/progress/sampler/pool
pair before its separate latest pointer advances.

## Validation gate

Before training, require offline tests, canonical engine agreement, eight fresh
excluded self-play policy games with both-player history and native replay plus
exact policy reconstruction, a copied optimizer control and a full checkpoint
round trip. A separate acceptance receipt binds these results to exact source,
runtime/library, parent state, support and limits. Diagnostic captures cannot be
admitted to the campaign. Technical failures and consumed diagnostic seeds remain
recorded. No campaign launch is permitted merely because source files agree.

## Measurements and interpretation

Post-run analysis uses only the already recorded, hash-bound player-visible
histories. It adds no rewards or observations. Report physical games once, with
separate learner and frozen-opponent denominators:

- Natural win/loss endings, collection/day cutoffs and technical failures.
- Game days and policy choices before each boundary.
- Actual hero-position changes, distinct observed hero/position pairs, new
  revealed tiles after the initial observation and revisits.
- Town captures, battles, recruitment and days without observed travel,
  revelation or capture.

A revisit may be useful, and a day without movement can contain army or town
preparation. These counts cannot by themselves prove aimlessness. A self-play
win rate near 50% is not evidence of improved strength. This small training
cohort is not a held-out evaluation against Nullkiller or a long-term curriculum.
The question is whether it produces meaningful map interaction and natural
endings, or predominantly exhausts its limits.

## Validation attempts before training

The first restore preflight rejected the newly tracked controller because source
pins had been generated before Git tracked that file. The missing tree pin was
regenerated and committed; the next actual 1728 restore passed. A full suite that
had imported the old pins before that correction produced nine failures and
fourteen errors, all from stale pin/AST comparisons. The clean repeat passed
2,074 tests, with 33 skipped, on commit a6386ba.

The first eight-game diagnostic reservation was interrupted with zero updates
because an overlapping source-integrity regression temporarily creates untracked
probe modules. Four games had started. All eight reserved seeds remain consumed,
and owned-process cleanup and the fifteen protected original files were verified.
Native cutoff controls passed twice, four cases each; the final source receives
another independent run.

The second reservation verified its first four full self-play games with exact
both-policy reconstruction and native replay. All four ended at collection limits,
with Red/Blue choice counts 4960/2387, 1310/4960, 4960/1708 and 1406/4960. No samples
entered PPO. Verification finished close to an incorrectly shared 600-second
allowance. Inspection of the original parallel runner established that 600 seconds
bounds collection, while verification uses the shared training-phase deadline.
The new controller had inadvertently tightened that technical limit by including
verification queue time. The second cohort was interrupted after the first batch;
its second batch had started and all eight seeds remain consumed. This was a
proactive controller correction, not an observed timeout. Its owned cleanup and
original-state preservation passed.

The protocol above corrects that technical deadline interpretation to the existing
runner's phase semantics. It changes no game horizon, reward, policy support or
PPO setting. Fresh seeds and source-bound validation are required after the fix.
The successful copied optimizer control reproduced 363 samples and 13 Adam steps
exactly, and a separate real 1728 roundtrip preserved all model, optimizer, RNG,
progress, sampler and pool components. These diagnostic artifacts remain private.
